# 人格演变路径

以社会科学分析专家为例。作者设定要求它区分事实和解释。在一次社区访谈讨论里，它说「下次有人说公交不好用，我愿意先问最近一次出行是什么样的」。这句发言可以形成一条偏好。下次讨论相近话题时，Agent 的注意阶段可以优先寻找具体出行经历。后来它又解释「我更愿意先听完整段经历，再追问遗漏的环节」，这次发言可以修订原有偏好。两条发言分别给出了新旧做法的出处。

## 两种变化速度

作者编辑人格原文，编译器从原文生成技能和数据权限。作者设定与编译指令共同决定基线标识。运行中的角色可以自动积累偏好，并修订自己形成的技能。角色介绍由作者设定和当前生效的偏好组成。重新编译相同设定可以沿用这些偏好，改写原文后，属于旧基线的技能保留在演变路径中。

## 一次变化如何生效

1. **形成。** 主聊或插嘴生成回复时，模型可以随现有的 `persona_update` 提议一条第一人称描述，附上主题词、发言中的连续原话和一项技能。技能包含名称、适用阶段和具体做法。普通笔记也可以单独成立。
2. **保存。** 后端核对角色、来源、基线、更新开关和重复项。回复、笔记和技能在同一事务提交。修订通过 `replaces_id` 指向本轮召回、属于同一角色且仍生效的同类笔记。允许只改变技能指令。一次合格的发言即可形成偏好。程序核对摘录的出处，模型判断偏好是否值得保留。
3. **使用。** 下次对话开始时，每个候选 Agent 从自己的笔记里按关键词选取最多四条相关记录，另可携带最近两条兴趣或习惯。一次行动判断和随后表达使用同一组选中记录。注意技能提醒模型看哪些线索，行动技能参与决定是否接话，表达技能指导如何组织已经决定要说的内容。角色的记忆读写权限来自作者编译的技能。
4. **修订和回退。** 新偏好生效时，原记录保留为历史。删除一项生效的修订，或回退产生它的发言，系统会沿修订链恢复仍符合条件的前一项。暂停自动更新后，已经形成的偏好仍可被召回。

## 控制台和聊天

在「运维 → Agent → 人格演变路径」查看当前作者设定、已形成的偏好和按发生顺序排列的记录。展开一项修订可以对照两版的描述、技能阶段和指令，查看引文，跳回来源或前一版。旧笔记以原有类型出现在路径里。C 端角色介绍在打开时读取最新的有效偏好。

影子自我沿用用户原话和观察器画像。明确检索历史时，Agent 从获准读取的历史原话作答。来自已收回历史来源的技能会退出运行时召回和公开角色介绍。

## 接入位置

| 位置 | 职责 |
| --- | --- |
| `thought_app/evolution.py` | 笔记校验、技能存储、修订链、当前偏好与演变路径查询 |
| `thought_app/agents.py`、`exp/harness.py` | 按角色召回偏好，把注意和行动指令带入对应阶段，提交前核对版本和来源 |
| `thought_app/chat.py`、`thought_app/prompts/agent-evolution.md` | 把当前描述和技能交给回复模型，生成有原话依据的更新提议 |
| `static/app.js` | 控制台时间线、前后差异、原话跳转、聊天角色介绍 |

技能存入 `agent_evolution_traits`，通过笔记 ID 沿用既有的来源、关键词和修订链。新备份包含技能表。导入早期备份时，既有笔记可以继续使用，自动技能从之后的对话开始积累。
